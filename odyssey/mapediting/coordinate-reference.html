Coordinate Reference

How Tiled's 2D coordinates translate to the game's 3D world.

Understanding coordinate systems is essential for debugging warps, spawns, touchplates, and other features that reference specific positions. Tiled uses a 2D grid, while Odyssey renders a 3D world — this page explains how they relate.

Tiled's Coordinate System

In Tiled, the map is a 2D grid:

  • X increases left to right (columns)
  • Y increases top to bottom (rows)
  • The origin (0, 0) is at the top-left corner
  • Tile coordinates are integers: column 0, 1, 2... and row 0, 1, 2...
  • Pixel coordinates = tile coordinate × 32 (since tile size is 32px)
Tiled Coordinate System (0,0) (1,0) (2,0) (3,0) ... X increases → (0,1) (1,1) (2,1) (3,1) (0,2) (1,2) (2,2) (3,2) (0,3) (1,3) (2,3) (3,3) | Y increases ↓

Game World Coordinate System

Odyssey uses libGDX's 3D coordinate system:

  • X increases eastward (same direction as Tiled X — left to right)
  • Y increases upward (vertical height — no equivalent in Tiled)
  • Z increases southward (opposite direction to Tiled's screen space)
Game World Coordinate System (3D) Y (up) | | |_______ X (east / right) / / Z (south / into screen) Floor is at Y = 0 Walls extend from Y = -height to Y = +height Ceiling is at Y = ceilingHeight × 2

The key relationship: Tiled's Y axis maps to the game's Z axis, but the conversion depends on whether you are working with tile layers or object layers.

Tile Layer Coordinate Conversion

When libGDX loads a TMX file, it automatically flips tile layer data so that row 0 is at the bottom (not the top, as in Tiled). This means a tile at Tiled position (x, y) ends up at libGDX tile position (x, mapHeight - 1 - y).

To convert a Tiled tile position to a 3D world position:

// Tiled tile coordinates -> 3D world position worldX = tiledX + 0.5 // Center of tile worldY = 0 // Ground level (for floor) worldZ = (mapHeight - 1 - tiledY) + 0.5 // Flip Y, center of tile

The + 0.5 centers the position within the tile (each tile is 1 world unit wide).

This flip is why doors use flipped Y internally. When you reference door positions (e.g., in touchplates), you use Tiled coordinates and the engine handles the conversion.

Object Layer Coordinate Conversion

Object layers are parsed differently from tile layers. The engine reads the raw XML pixel coordinates and converts them directly to world coordinates without flipping Y:

// Object layer pixel coordinates -> world position worldX = pixelX / 32 // Divide by tile width worldZ = pixelY / 32 // Divide by tile height (no flip!) worldWidth = pixelWidth / 32 worldHeight = pixelHeight / 32

This means that for object layers (Warps, Spawns, NM, Keep, TP zones, etc.), a rectangle drawn at Tiled position maps directly to the same relative position in the game world. You do not need to think about Y-flipping when drawing object layer zones.

Layer-Specific Coordinate Notes

Warp Target Coordinates

Warp x and y properties specify the target tile position using the same coordinates you see in Tiled. The player will appear at the center of that tile on the destination map.

Touchplate Door Coordinates

Touchplate x and y properties also use Tiled coordinates. Hover over the target door tile in Tiled and read the coordinates from the status bar. The engine internally flips the Y to match the door's stored position.

Bootmap Target Coordinates

Same as warps — the x and y properties use Tiled coordinates for the destination position on the target map.

Vertical (Y) Position Reference

The vertical axis (Y) is determined by the layer type and configuration:

Element Y Position Notes
Floor 0 Base ground level
Floor2 0.001 Slightly above floor to prevent z-fighting
Wall base -height Default height=1, so base is at -1
Wall top +height Default height=1, so top is at +1
Point lights 1.0 + oy Default Y = 1.0 (middle of a standard wall), adjustable via oy offset
Ceiling ceilingHeight × 2 Default ceilingHeight=1, so ceiling is at Y=2
Roof eaves wallHeight × 2 Eaves start at the top of the walls
Roof peak eaves + roofHeight × 2 Depends on roof_angle and roof width

Quick Conversion Reference

From To Formula
Tiled tile (x, y) World (X, Z) X = x + 0.5, Z = (mapHeight - 1 - y) + 0.5
Object pixel (px, py) World (X, Z) X = px / 32, Z = py / 32
World (X, Z) Tiled tile (x, y) x = floor(X), y = mapHeight - 1 - floor(Z)
Tiled tile Y libGDX tile Y libgdxY = mapHeight - 1 - tiledY

Visual Example

Consider a 4x4 map. Here is how Tiled coordinates map to the game world:

Tiled (top-down): Game World (3D top-down view): (0,0) (1,0) (2,0) (3,0) (0.5,3.5) (1.5,3.5) (2.5,3.5) (3.5,3.5) (0,1) (1,1) (2,1) (3,1) (0.5,2.5) (1.5,2.5) (2.5,2.5) (3.5,2.5) (0,2) (1,2) (2,2) (3,2) (0.5,1.5) (1.5,1.5) (2.5,1.5) (3.5,1.5) (0,3) (1,3) (2,3) (3,3) (0.5,0.5) (1.5,0.5) (2.5,0.5) (3.5,0.5) Y increases downward Z increases downward (but rows are flipped) Tiled (0,0) = top-left World (0.5, 3.5) = top-left visually Tiled (0,3) = bottom-left World (0.5, 0.5) = bottom-left visually

Notice how Tiled's row 0 (top) corresponds to the highest Z value in the world, and Tiled's bottom row corresponds to the lowest Z value. The X axis is unchanged.

Practical Tips

  • For warps and bootmaps: The x,y properties use the same system as Tiled. Hover your mouse over the target tile in Tiled and read the coordinates from the status bar.
  • For touchplates: Same as above — hover over the door tile and use those coordinates.
  • For object layer zones: Just draw the rectangle where you want it in Tiled. The coordinate conversion is automatic.
  • When debugging: If something appears in the wrong position, check whether the Y coordinate needs to be interpreted as Tiled (top-down) or world (bottom-up). The server log outputs both coordinate systems for most layers.
